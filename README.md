# MarkingCodes TCP

Сервер и клиент на .NET 10 для передачи кодов маркировки по TCP.

Сервер раз в 500 мс генерирует код и шлет всем подключенным клиентам. Клиент пишет коды в файл, по одному на строку, и переподключается, если связь пропала.

## Запуск

```bash
dotnet run --project src/MarkingCodes.Server -- [port]                      # по умолчанию 5000
dotnet run --project src/MarkingCodes.Client -- [host] [port] [outputFile]  # 127.0.0.1 5000 codes.txt
```

Остановка - Ctrl+C или SIGTERM.

Тесты: `dotnet test`

## Формат кода

```
01<GTIN-14>21<серийный номер, 13>GS91<ключ, 4>GS92<подпись, 44>
```

GS - символ 0x1D, в файл пишется как есть. У GTIN правильная контрольная цифра.

## Протокол

Каждое сообщение: 4 байта длины (big-endian) + строка в UTF-8. Клиент сначала читает заголовок, потом ровно столько байт, сколько в нем указано, поэтому склеенные или разрезанные пакеты не мешают. Длина больше 64 КБ считается ошибкой, соединение рвется.

## Что учтено

- Каждый клиент на сервере обслуживается отдельно, отключение одного не влияет на других.
- Сервер замечает отключение клиента по чтению из сокета, а не только по ошибке записи.
- Клиент переподключается через 2 с после любой ошибки.
- Если от сервера 5 с нет данных, клиент считает соединение мертвым и переподключается (на случай, когда сервер пропал без закрытия соединения).
- Файл открыт в режиме дозаписи с AutoFlush.

Коды, сгенерированные пока клиент был отключен, не досылаются - в задании этого не требовалось.
